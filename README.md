## 本次范围

依据 `文档/TripGuessr_携程拾景漫游_产品介绍.docx` 的产品机制制作，以用户本次要求为范围：一个大同目的地、每景点一张图片，页面沿用所给 Trip.com 首页参考的蓝白配色、圆形入口和圆角卡片。

完整流程：携程首页的 TripGuessr 入口 → 神秘目的地封面 → 云冈石窟 / 华严寺 / 悬空寺的线性探索 → 三题挑战 → 每题解析 → 大同揭晓与兴趣标签 → 1—3 日路线 → 本地行程单。

其他交互：线索册、中文/英文线索解释、浏览器语音朗读、图鉴、日榜/好友榜/主题榜、收藏、示例权益、SVG 挑战卡下载。

## 原型规则与边界

- 用户仅要求一个目的地，因此今日进度为 1 城、满分 100，不显示虚构的其余 4 个目的地。
- 探索默认 180 秒，为原型实现假设；时间到自动进入三题挑战，不按探索速度扣分。提前结束时仅使用已浏览场景的题目。题目按 30 / 30 / 40 分计分，每次提交立即反馈。
- 探索照片铺满手机可视区域，默认在覆盖画面的基础上放大至 115%；支持单指/鼠标拖动、双指捏合、滚轮、加减按钮和复位，最大 350%。热点跟随照片坐标，文字保持屏幕字号；未生成视频或修改原图。
- 每景点 3 条交互线索。英文切换作用于线索正文，中 / EN 按钮切换线索正文，不代表全应用多语言。
- 语音是浏览器文字朗读，不是景区环境录音；能否播放取决于本机语音引擎。
- 兴趣标签由线索点击类别计数形成；无点击时标注文化探索，不假称模型推断。
- “AI 路线”为预设示例，按点击兴趣显示主题，天数切换实际更换行程内容；没有接入模型或实时交通。
- 排行榜其他用户为演示数据；仅满分解锁示例权益，未接入真实排名与前 30% 权益规则。权益无实际兑换效力。
- 旅行服务弹层提供携程官网外链，不虚构价格、库存、可预订状态或订单。
- 结果、收藏、领取状态、行程存在本浏览器 localStorage。探索中的进度仅保留在当前页面内；刷新会结束未完成探索。file:// 与 http:// 各自保存数据。
- 分享按钮生成本地 SVG 卡片，由用户自行分享，无自动发送行为。

## 照片库

```text
photo-library/
  datong/
    yungang/original.jpg     云冈石窟，3072 × 4096，3:4
    huayan/original.jpg      华严寺，2304 × 4096，9:16
    xuankong/original.jpg    悬空寺，3072 × 4096，3:4
    city-wall/original.jpg   带黑边的城墙截图，待替换，不用于探索
  shuozhou/
    yingxian/original.jpg    应县木塔，周边储备，不用于大同关卡
```

索引是 `data.js` 内的 `PHOTOS`，包含城市、景点、尺寸、状态、来源文件名、备注和相对路径。`SCENES` 是探索场景配置。新增照片时先放入对应城市/景点目录，再补充索引；需要加入探索时再编辑场景与题库。

竖屏宽高比按 **9:16 至 3:4** 理解，对应用户要求的竖向 16:9 至 4:3。采用的三个原图短边均高于 1080 像素，未放大、未重绘、未篡改文件。网页通过 CSS 容器适配。城墙图片虽然文件像素较大，但实际有效区域为横向照片且有手机界面，所以没有将截图尺寸当作可用竖图清晰度。所有根目录原文件均保留。

## 检查

`check.cjs` 使用本机已提供的 Playwright 与 Edge 检查实际浏览器交互，不是部署测试。`check-result.json` 保存主链路结果。`preview-*.png` 为浏览器截图。`check-viewer.cjs` 覆盖全屏边界、115% 初始缩放、滚轮、鼠标拖动、浏览器原生双指触摸事件、复位、关闭讲解后画面不偏移，以及三景切换。

已覆盖正确与错误计分、提前结束、线索交互、三种路线天数、收藏与行程保存、刷新恢复行程、下载分享卡、手机横向溢出与素材筛选。浏览器语音是否发声、真实手机触控以及真实携程预订不在自动化验收范围内。

## 移动设备适配（2026-09-19）

- `device.js` 在页面渲染前识别手机、Android 平板及使用桌面 UA 的 iPad；Windows 触屏电脑保留桌面展示。
- 移动设备不受 480px 模拟机宽度限制：整个浏览器可视区域直接展示应用，去掉侧栏、手机边框、模拟状态栏与底部横条。
- `mobile.css` 使用动态视口高度和系统安全区，适配横竖屏、地址栏引起的视口变化；旧浏览器回退到 window.innerHeight。
- 沉浸覆盖网页可用区域，浏览器自身的地址栏由浏览器控制，不强制请求系统全屏。
- `check-mobile.cjs` 已通过 Chromium 下的 iPhone/Android 设备模拟、iPad 桌面 UA 和多触点模拟、横屏安全区变量模拟、视口调整及答题到行程保存流程。这不等同于实体 iOS Safari/Android 手机验收。
