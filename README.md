## 入口分流：今日挑战 / 社区

携程首页的 TripWonder 入口先进入分流页（`community.js`），选择「今日挑战」或「社区」。两个入口为上下等分的圆角立体卡片，按住时按触点方向倾斜下沉，松开回弹；点击后从卡片中心向外展开进入下一页：

| | 今日挑战 | 社区 · 官方目的地 | 社区 · 玩家 Journey（UGC） |
|---|---|---|---|
| 内容 | 当天抽取的官方目的地 | 本机挑战过的官方目的地（防剧透） | 审核通过的玩家 Journey |
| 玩法 | 探索 + 答题共用 1 分钟倒计时，无讲解点 | 浏览场景，有讲解点，无题目与计时 | 与今日挑战相同的限时玩法 |
| 留言板 | 不显示 | 显示（详情页列表 + 场景气泡） | 发布者选择是否开启；完成挑战后可见 |
| 优惠 / 徽章 / 奇境币 / PK / 排行 | 有 | 无 | 无 |
| 标记 | — | 卡片显示城市徽章（领取后点亮） | 卡片盖「已挑战」戳 |

社区默认进入「广场」，混合展示已挑战的官方目的地与审核通过的玩家 Journey；可切换「已挑战」或「玩家 Journey」筛选。内容采用作者信息、关注、正文、照片、地点与评论互动区组成的帖子卡片，单图竖排、多图横排，右下角悬浮「+」进入发布表单。关注与帖子点赞只保存在本机 `tripwonder-v2`，不代表真实线上互动；评论入口打开该 Journey 的留言板，继续遵循挑战后解锁及发布者关闭留言的规则。

挑战过的官方城市与玩过的 UGC 记在本机 `tripwonder-v2.challenged` / `ugcPlayed`，刷新后保留。UGC 帖子在挑战前使用不含地名的挑战标题，完成后才显示地点标签。社区「+ 发布」目前是表单原型（本机校验，不上传）；正式 UGC 由后台「添加 Journey」选择「玩家 UGC」生成，审核通过后进入社区（见下文后台一节）。示例 UGC（厦门沙坡尾、重庆十八梯、成都东郊记忆）在 `content/ugc.js`，照片为 Wikimedia Commons 授权素材，署名见 `photo-library/ugc/ATTRIBUTION.md`，展示版本由 `node scripts/build-ugc-media.cjs` 生成。已知限制：直接双击 `index.html`（file://）时 UGC 场景无法载入球面画面，需通过 HTTP 预览。

## 今日挑战

今日挑战打开当天第一个待探索目的地的封面；本次页面体验首次进入封面时自动弹出玩法说明，右上角“玩法”可随时重开。每天依据本地日期，从完整目的地库（当前八座城市）随机抽取五座不同城市，当天顺序固定。封面底部为玻璃工具栏：图鉴、排行榜、PK 对战，以及“开始挑战”按钮；没有“跳过”按钮，也没有圆点或滑动提示。直接左右滑动照片可循环切换这五个目的地，桌面可拖动、横向触控板滑动或在照片聚焦后使用左右方向键。切换前等待下一张照片载入，失败时留在当前目的地；切换后返回会保留本次页面体验的场景与线索进度。图鉴与今日成绩沿用这五座城市，完成后可从结果继续下一目的地。好友链接仍支持全库目的地，若不在当天五城中，会替换本次五城中的最后一座以接受挑战。刷新页面仍会清空挑战进度、结果、示例权益、收藏及行程，从首页重新开始，当天抽取的城市保持不变。

各目的地有 1–4 张探索照片；张家界包含天子山峰林、云雾峰林、天门洞与通天大道四个场景。每张照片的三个讲解点只在社区浏览时显示，今日挑战不显示讲解点和留言，题目只凭画面与常识即可作答。进入第一处场景即开始 1 分钟倒计时（目的地可用 `rules.challengeSeconds` / 后台 `rules.quizSeconds` 调整），探索与答题共用，返回封面也不暂停；任何场景都可点「去答题」，最后一处为「开始答题」。左上角返回回到封面，再次进入继续当前场景与剩余时间。支持拖动、双指缩放、滚轮、键盘方向键。

探索与答题页共用屏幕边缘光带：开始时整圈亮蓝，从顶部中央沿左右两侧同步向下消退，最后 15 秒变红并逐渐减慢，归零时收拢至底部中央；切换场景与答题页沿用同一进度，离开计时页面隐藏。三道题每题 20 分，与探索共用同一倒计时；剩 15 秒计时变红，最后 10 秒每秒脉冲一次并配轻微滴答声（跟随背景音乐静音设置）和手机震动，探索页与答题页都会提示。答题页左上角返回刚刚最后一处场景，计时继续；再次进入答题沿用当前题目与已选答案。到时自动提交当前已选答案，未作答题目计 0 分。提交时只进入下一题、不公布对错。答完或到时后进入不限时的地图定位；答题时间仍有剩余时可返回修改第三题，沿用剩余时间。在中国地图上轻点放置落点，可拖动、双指或滚轮缩放，确认前可反复调整，可回看本目的地全部实景及已读线索。确认后左上角按钮改为返回首页，地图自动框出落点与真实位置并连线，显示直线距离和定位得分（落点与目的地在同一城市（地级市；直辖市、特别行政区按整体计）即满分 40 分；不同城市按距离计分，25 公里内满分，之后按 450 公里尺度指数衰减；城市可用 `guess` 字段单独配置）。结果页展示综合成绩 = 定位 40 + 三题 60，以及落点、真实位置和距离的小地图。完成后可收藏城市、查看图鉴及今日进度、保存分享卡，并分别领取目的地纪念徽章与景点门票优惠券。分享链接可让好友在同一关卡挑战，打开后好友作为 PK 对手（按链接分数复原一局）；需要把网页发布到双方都能访问的地址才能跨设备使用。演示好友榜不代表真实用户排名。

结果页分别展示纪念徽章与“优惠权益 · 目的地”两个领取模块，权益位于徽章模块下方，领取状态相互独立。点击“领取权益”打开独立权益弹窗，领取后可再次查看。徽章弹窗只展示城市徽章正面、超越比例与“收下徽章”按钮，保留入场和缩小淡出的退场动画，不再翻转或展示优惠信息。优惠券为满 100 元可用的 20 元景点门票券，前端记录有效期为领取后 30 日；再次查看不延长有效期，记录仍只保存在本次页面体验。领取操作原位更新按钮，不重建结果页，保留展开状态与滚动位置。奖励页的“超越比例”暂由本局分数通过固定曲线估算，并非真实用户成绩统计；优惠券兑换未接入。

路线页使用本地策划的景点和兴趣标签生成一至三日安排，可调天数、节奏、兴趣、出发日期，替换和调整停留地点；保存的行程仅在本次页面体验中可查看。已知的周闭馆日及部分开放时段会用于调换日期分组或标出冲突；未收录的开放时间仍需人工核实。交通时长由两点距离粗估，景点停留时间为规划建议；库存、价格、预订与优惠券兑换均未接入。产品按钮仅演示携程业务承接。

原图统一为 `photo-library/<城市>/<景点>/original.<原格式>`，未采用素材集中在 `photo-library/_unused/<城市>/`；目录与加载规则见 [照片素材规范](photo-library/README.md)。`photos.html` 展示采用素材和署名。大同源图由用户提供，拍摄权属未独立验证。其他城市素材（Pexels、Wikimedia Commons 与 Unsplash 照片）的作者、许可、识别依据和未采用素材，见各城市的 ATTRIBUTION.md / SOURCES.md。`content/*.js` 是景点、线索、题目和路线站点数据；`catalog.js` 汇总八城并建立媒体索引。每个目的地 1–4 处实景（苏州一处，张家界四处，其余三处），题目固定 3 道；探索页用 `immersive-viewer.js` 沉浸查看，各景配置见 `immersive-scenes.js`。探索页将原图贴在球体内壁，视点固定在球心，按实际图片比例自动计算转头范围，不依赖深度图。支持任意横图比例，并兼容已有竖图；使用原图分辨率的沉浸素材，支持最高 3 倍放大；切换时以过渡动画覆盖加载，下一处首帧渲染完成后再显示，失败时保留当前画面并可重试。图鉴等非沉浸页面使用缩略图。

探索页按目的地播放背景音乐：八座城市各一首原创配乐（大同《云冈晨钟》、北京《红墙金瓦》、苏州《姑苏塔影》、桂林《漓水青峰》、张家界《峰林云海》、上海《外滩旧梦》、深圳《湾区之光》、香港《维港夜色》），由 `scripts/build-bgm.cjs` 在本地用纯合成音色（拨弦、笛箫、钟磬、人声、合成器与鼓组）生成，不含采样或第三方录音。运行 `node scripts/build-bgm.cjs --ffmpeg <ffmpeg 路径>` 可重新生成 `assets/bgm/*.mp3`（每首约 0.8–1.1 MB，响度约 −18 LUFS）和 `bgm-manifest.js`。每个文件是一段 60 或 64 秒的循环外加 3 秒交接，`scene-bgm.js` 用 Web Audio 每隔一个循环长度启动一份副本，前后副本重叠后无缝衔接。音乐只在探索页播放，同一目的地内切换场景不中断；离开探索页淡出并暂停，从答题页返回时接着播放。封面会预取当前目的地的音乐（省流量模式除外）。浏览器要求页面先有一次点击或按键才能出声。直接双击打开 `index.html` 时浏览器不允许读取本地文件，播放器改为加载 `bgm-local/*.js`（同一份 MP3 的脚本封装，由同一脚本生成，只供本地预览，不进入网站和 Android 构建）。打开线索时音乐自动压低，朗读线索时进一步压低；收藏按钮左侧的喇叭按钮可开关音乐，选择保存在本机。`check-bgm.cjs` 检查循环衔接、播放、压低、静音与答题往返。

本轮仍暂缓动态场景。地图边界来自 DataV.GeoAtlas（`assets/map/`），由 `scripts/build-china-map.cjs` 预投影、简化为 `china-map.js`（约 45 KB，省界 + 省会，四色区分相邻省份）；地级市边界另存为 `china-cities.js`（约 112 KB，363 个地市，直辖市/港澳整体显示，DataV 未提供台湾地市数据），只在放大到一定程度时才加载和显示。运行时不解析 GeoJSON、不加载瓦片；平移只移动一个合成层，地图移动时底部卡片暂停实时模糊。确认落点后地图自动缩放，让落点与答案同时完整可见。距离与计分目前在前端计算，文档中的服务端计分尚未接入。`media.js` 保留未来视频接入所需的海报回退与首帧显现能力，但这版各目的地内容都只有静态照片，尚无真实景点视频。浏览器及设备实际表现应以目标手机测试为准。

## 游戏化（本机存储）

以下内容只保存在本机浏览器（`tw-store.js`，localStorage 键 `tripwonder-v2`），存储被禁用时退回内存，页面照常可用。个人页「重置演示数据」可一键清空。地址加 `?off=wallet,pk,bubbles`（任选）可在现场临时关闭对应功能。

| 功能 | 状态 | 说明 |
|---|---|---|
| 奇境币 | 已实现（本机） | `wallet.js`。每 10 分 1 枚；点亮徽章 +5；答题剩余每 15 秒 +1（最多 +3）；PK 胜 +10、平 +3；当天完成 3 城 +10。同城同日只补发超过当天最高分的部分，判断依据存于本机，刷新也不会重复发放。 |
| 兑换与商家位 | 示例 | `offers.js`。优惠券与「商家专区」均为示例，券码只用于演示；城市专属商家只对已有成绩的城市显示，避免提前泄题。待接入携程真实优惠与商家数据。 |
| 模拟对手 PK | 已实现（模拟） | `pk-mode.js`。封面「PK 对战」匹配一位虚构对手（新手 / 达人 / 学霸），同城同日同对手结果固定；答题页只显示对手进度，不显示对错；地图揭晓时显示对手落点；结果页 VS 卡。好友挑战链接会把好友变成对手。 |
| 场景留言气泡 | 已实现（本机 + 示例） | `scene-bubbles.js`、`content/bubble-seed.js`。只在社区浏览场景时显示（今日挑战不显示，防剧透）。浮动气泡按「去过 / 没去过」分类，可筛选、关闭、点赞；「留言」后轻点画面选择位置。社区详情页的留言板汇总同一 Journey 全部场景的留言。示例留言不含任何地名。 |
| 探索过的场景 | 已记录 | 存于 `tripwonder-v2.explored`，供之后「选场景交给携程 AI 规划行程」使用。 |

正式探索页已经使用球面查看器替换旧圆柱投影。未来上传模块只需向场景提供稳定照片 ID、可读取原图地址和内容版本，即可自动使用球面呈现，无需逐张配置深度或执行图片重绘。上传接口本身尚未实现。具体契约、构建和验收步骤见 [球面照片接入流程](docs/sphere-photo-workflow.md)。

## 后台：目的地旅程库（photos.html）与添加 Journey

运行 `node admin/server.mjs`（Node 22+，需要 `node:sqlite`；默认 http://127.0.0.1:8787/，只监听本机），打开 `/photos.html`：

- 按目的地展示，一个目的地一张卡片，点击进入该目的地的场景、讲解点、题目与规则；内置八城为只读，数据库中的目的地可审核、停用、删除。
- “添加 Journey”（`journey-new.html`）：先选类型——官方（进入今日挑战）或玩家 UGC（需填写不含地名的挑战标题、发布者昵称、是否开启留言板；审核后进入社区，不参与优惠与成就）；再填写目的地信息、上传 3–9 张场景图、设定规则（挑战总时长、三题分值、定位满分与距离衰减；三题分值 + 定位满分须为 100）。提交后创建后台任务，依次执行：图片转换（thumb / screen / detail WebP；探索页用原图，由球面查看器按需生成） → 每个场景由 MiMo 看图生成 3 个讲解点 → 生成 3 道题、地图坐标与路线站点 → 校验并写入 SQLite（`admin/data/tripwonder.db`）。步骤失败可从失败处重试，已完成的步骤不会重做。
- 提示词在 `admin/prompts/*.md`，可直接编辑；输出由 `admin/pipeline.mjs` 校验（禁用词防剧透、坐标范围、选项与答案位置等），不合格会带着原因自动重试。生成内容默认“待审核”，坐标由模型推断时会标出“待核对”。
- 游戏通过 `/db-journeys.js` 读取状态为“已上线”的数据库目的地：官方目的地由 `catalog.js` 并入今日挑战的目的地池；玩家 UGC 还须“已审核”，由 `community.js` 放进社区；`app.js` 读取每个目的地的 `rules`。纯静态部署没有该脚本，目的地池和之前一致，`photos.html` 退回只读预览。
- MiMo Key 从环境变量 `MIMO_API_KEY`、`admin/mimo.key` 或上级目录的 `mimo api key.txt` 读取，只在服务端使用；模型默认 `mimo-v2.6-flash`（不用 pro）（`MIMO_MODEL` 可改，`MIMO_THINKING=off` 关闭思考以提速）。
- 数据库表 `destination_journeys(destination_id, journey)` 存 journey 文档（JSON），状态与任务另存于 `journey_meta`、`jobs`。
