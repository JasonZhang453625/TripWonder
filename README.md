# TripWonder 携程 · 奇境挑战

GitHub 仓库：[JasonZhang453625/TripWonder](https://github.com/JasonZhang453625/TripWonder)（私有）。项目仍由仓库所有者管理；需要协作时，在 GitHub 仓库的 Settings → Collaborators 中邀请指定账号。未提供协作者账号前不预先添加成员。

协作发布使用所有者账号生成 merge commit，执行 `npm run release:merge -- <PR编号>`；避免协作者 squash 提交导致 Vercel Hobby 阻止部署。构建检查、发布和验收见 [发布流程](docs/releasing.md)。

打开 `index.html`，或在本目录运行 `python -m http.server 8765 --bind 127.0.0.1` 后访问 `http://127.0.0.1:8765/`。这是可直接在浏览器打开的静态 HTML 原型；入口页的 3D 卡片需要 HTTP 预览（直接双击打开 file:// 时浏览器禁止 WebGL 读取本地图片，只能显示普通卡片）；当前工作区修改没有自动代表线上部署。

## 入口分流：今日挑战 / 社区

携程首页的 TripWonder 入口先进入分流页（`community.js`），选择「今日挑战」或「社区」。两个入口由 Three.js 在单个画布中渲染为上下等分的圆角挤出模型，带柔和倒角、侧面高光和轻微浮动。按住时整块卡片朝触点倾斜并整体下沉，表面始终保持平直且尺寸不变，松开后以阻尼弹簧回弹，再从卡片中心向外展开进入下一页。无 WebGL 时保留原生按钮，减少动画模式关闭浮动；首页会提前解码卡片图片、异步编译材质并绘制首帧，进入时直接复用；预备画布静止且不可交互，不等待无关字体，慢图片不会阻塞导航。进入挑战或社区时会暂停并缓存一套卡片模型、纹理和画布，返回时直接恢复；完成数量或入口照片变化时只更新对应卡面。缓存期间不渲染，不因隐藏尺寸变化重建模型；返回携程首页或离开此流程时释放资源。源码为 `hub-cards-src.js`，通过 `npm run build:hub` 合并进现有 Three.js 查看器包：

| | 今日挑战 | 社区 · 官方目的地 | 社区 · 玩家 Journey（UGC） |
|---|---|---|---|
| 内容 | 当天抽取的官方目的地 | 本机挑战过的官方目的地（防剧透） | 审核通过的玩家 Journey |
| 玩法 | 探索 + 答题共用 1 分钟倒计时，无讲解点 | 浏览场景，有讲解点，无题目与计时 | 与今日挑战相同的限时玩法 |
| 场景留言气泡 | 不显示 | 浏览场景时显示 | 发布者选择是否开启；挑战中可查看和放置 |
| 独立评论区 | 不显示 | 详情页可评论、回复和点赞 | 完成挑战后解锁，不受气泡开关影响 |
| 优惠 / 徽章 / 奇境币 / 排行 | 有 | 无 | 无 |
| PK | 入口转入随机玩家 Journey | 无 | 已审核旅程参与 PK 池，无官方奖励 |
| 标记 | — | 卡片显示城市徽章（领取后点亮） | 卡片盖「已挑战」戳 |

社区默认进入「广场」，混合展示已挑战的官方目的地与审核通过的玩家 Journey；可切换「已挑战」或「玩家 Journey」筛选。内容采用作者信息、关注、正文、照片、地点与评论互动区组成的帖子卡片，单图竖排、多图横排，右下角悬浮「+」进入发布表单。关注与帖子点赞只保存在本机 `tripwonder-v2`，不代表真实线上互动；卡片的评论入口打开该 Journey 的独立评论区，玩家 Journey 完成挑战后解锁评论。

挑战过的官方城市与玩过的 UGC 记在本机 `tripwonder-v2.challenged` / `ugcPlayed`，刷新后保留。UGC 帖子在挑战前使用不含地名的挑战标题，完成后才显示地点标签。每条玩家 Journey 要求 3–9 张照片，发布表单、后台生成和社区目录使用同一限制。社区「+ 发布」已经接通投稿：照片原文件与三档展示图保存在 IndexedDB，填写内容自动保存草稿；「我的发布」可查看状态、退回原因并修改重提。无后台时通过「本机审核」检查照片、坐标、三道原题和答案，通过后才加入本机社区，也可退回或下架。连接 `node admin/server.mjs` 后实际上传照片和用户原题，经服务器处理后进入后台审核；不调用 AI 改写用户原题，后台另行录入而未提供题目的 Journey 仍使用 AI 生成。该模式只用于原型，不包含账号、共享社交数据或生产审核权限。示例 UGC（厦门沙坡尾、重庆十八梯、成都东郊记忆）在 `content/ugc.js`，各有 3 张不同实景照片，配套三道题与每张三个讲解点。2026-10-17 素材重初始化后，仅这三条示例的已挑战记录会重置一次，官方进度、用户创建的 Journey 和留言保留；后续刷新不会重复重置。照片为 Wikimedia Commons 授权素材，署名见 `photo-library/ugc/ATTRIBUTION.md`，展示版本由 `node scripts/build-ugc-media.cjs` 生成。已知限制：直接双击 `index.html`（file://）时 UGC 场景无法载入球面画面，需通过 HTTP 预览。

社区详情页只展示顶部导航、横向照片轮播、名称与地区、纪念徽章及独立评论区；不再单独展示介绍、缩略图列表或浏览按钮。照片支持触摸左右滑动、鼠标拖动与键盘方向键。官方目的地点击当前照片进入对应场景的沉浸探索，返回时保留照片位置。玩家 Journey 从社区卡片的正文或照片点击后直接进入整轮限时挑战，不先打开详情页或挑战封面；照片对应同一个 Journey，探索、三题及地图定位使用同一轮进度。中途退出返回来源页，再次点击会重新开始整轮挑战；未主动退出时刷新恢复当前轮次。官方目的地的徽章位于图片右下角并向下探出。

独立评论区针对整个 Journey，支持评论、回复与点赞，使用 `tripwonder-v2.boardComments` / `boardReplies`；五位初始化用户的评论使用独立 ID。社区卡片的评论入口打开独立评论区，玩家 Journey 的评论在完成挑战后解锁。场景留言板是沉浸画面上带位置的气泡，使用 `tripwonder-v2.bubbles[sceneId]` 与场景预置留言。两套内容及点赞分别记录，发布气泡不会自动新增独立评论，发表独立评论也不会生成气泡。发布者的「开启场景留言气泡」只控制 `boardEnabled`：开启后玩家挑战时可查看和放置气泡，挑战中隐藏具体地名；关闭时隐藏气泡及其入口，不影响独立评论区。详情页底部输入栏发表独立评论，气泡开启时展开输入栏还可通过「在场景里留言」进入场景选择及定位气泡流程。

本机投稿可从结果分享面板导出 `.tripwonder.json` 文件，由另一设备在社区「导入旅程」后挑战；图片总量超过 70 MB 时需改走后台发布分享。预置、后台已发布和构建快照中的 UGC 均可用成绩链接直接开始挑战，UGC 链接不加入官方每日抽签；玩家好友链接可在同一 UGC 中比对成绩。不可用链接会明确提示。独立评论和气泡继续各自保存在本机，不因导出文件自动同步。

玩家共创与官方每日挑战共用答题交互：点击选项立即提交并揭晓，不显示确认答案按钮；揭晓后才显示「下一题」或「前往地图」。`node tests/ugc-quiz.browser.cjs` 从社区入口逐个检查预置玩家旅程，覆盖正确／错误答案、连点防重复、解析期间暂停计时及刷新恢复。

UGC 在探索、答题、地图和结果阶段刷新可恢复，倒计时按绝对时间继续计算，刷新不补时间；题目或素材版本变化时不恢复旧轮次。主动退出挑战、重新点击帖子会按新的完整一轮开始。官方今日挑战的刷新规则不变。

验收：`npm test` 包含共享出题校验、上传、并发重复提交、任务字段、原题保留、审核可见性、退回重提与构建导出。`node check-ugc-lifecycle.cjs` 实测本机闭环；设 `TRIPWONDER_URL=http://127.0.0.1:8787/` 可检查后台模式，使用独立测试目录与数据库以保留现有数据。浏览器检查另外覆盖草稿/照片恢复、挑战各阶段刷新、评论解锁、无奖励以及跨浏览器分享。

## 今日挑战

今日挑战打开当天第一个待探索目的地的封面；本次页面体验首次进入封面时自动弹出玩法说明，右上角“玩法”可随时重开。每天依据本地日期，从完整目的地库（当前八座城市）随机抽取五座不同城市，当天顺序固定。封面底部为玻璃工具栏：图鉴、排行榜、PK 对战，以及“开始挑战”按钮；没有“跳过”按钮，也没有圆点或滑动提示。直接左右滑动照片可循环切换这五个目的地，桌面可拖动、横向触控板滑动或在照片聚焦后使用左右方向键。切换前等待下一张照片载入，失败时留在当前目的地；切换后返回会保留本次页面体验的场景与线索进度。图鉴与今日成绩沿用这五座城市，完成后可从结果继续下一目的地。好友链接仍支持全库目的地，若不在当天五城中，会替换本次五城中的最后一座以接受挑战。刷新页面仍会清空挑战进度、结果、示例权益、收藏及行程，从首页重新开始，当天抽取的城市保持不变。

各目的地有 1–4 张探索照片；张家界包含天子山峰林、云雾峰林、天门洞与通天大道四个场景。每张照片的三个讲解点只在社区浏览时显示，今日挑战不显示讲解点和留言；三道题是「原来如此」式的趣味科普，只凭画面与大众常识即可作答，依次为热身（看图认物）→ 原来如此（原理/成因）→ 挑战（反直觉/综合推断）；出题规则统一见 [出题规范](content/QUIZ-SPEC.md)。进入第一处场景即开始 1 分钟倒计时（目的地可用 `rules.challengeSeconds` / 后台 `rules.quizSeconds` 调整），探索与答题共用，返回封面也不暂停；所有 Journey 只有到最后一处场景才显示「开始答题」，此前只显示上一处、下一处导航。左上角返回会提示放弃本次挑战，取消继续，确认回到封面重新开始。支持拖动、双指缩放、滚轮、键盘方向键。

探索与答题页共用屏幕边缘光带：开始时整圈亮蓝，从顶部中央沿左右两侧同步向下消退，最后 15 秒变红并逐渐减慢，归零时收拢至底部中央；切换场景与答题页沿用同一进度，离开计时页面隐藏。三道题每题 20 分，与探索共用同一倒计时；剩 15 秒计时变红，最后 10 秒每秒脉冲一次并配轻微滴答声（跟随背景音乐静音设置）和手机震动，探索页与答题页都会提示。今日挑战的探索、答题及地图定位页返回时会弹出放弃确认；取消留在当前页并继续计时，确认清空本次进度后回到今日挑战封面。到时自动提交当前已选答案，未作答题目计 0 分。点击选项即提交并当场揭晓，无需确认按钮：正确选项变绿、选错的变红，并显示一句解析；揭晓期间计时暂停，点「下一题」继续计时，第 3 题揭晓后点「前往地图」。答完或到时后进入不限时的地图定位；在中国地图上轻点放置落点，可拖动、双指或滚轮缩放，确认前可反复调整，可回看本目的地全部实景及已读线索。确认后左上角按钮返回今日挑战封面，地图自动框出落点与真实位置并连线，显示直线距离和定位得分（落点与目的地在同一城市（地级市；直辖市、特别行政区按整体计）即满分 40 分；不同城市按距离计分，25 公里内满分，之后按 450 公里尺度指数衰减；城市可用 `guess` 字段单独配置）。结果页展示综合成绩 = 定位 40 + 三题 60，以及落点、真实位置和距离的小地图。完成后可收藏城市、查看图鉴及今日进度、保存分享卡，并领取目的地纪念徽章；优惠券与商家权益统一在积分商城使用奇境币兑换。分享链接可让好友在同一关卡挑战，玩家 Journey 链接打开后可与好友成绩比对，官方链接只保留同关成绩比较；需要把网页发布到双方都能访问的地址才能跨设备使用。演示好友榜不代表真实用户排名。

结果页保留纪念徽章、本局奇境币和积分商城入口，不再展示优惠权益领取模块或商家推荐卡。优惠券与商家权益统一在积分商城使用奇境币兑换，兑换记录、示例券码和扣币明细由商城管理。徽章弹窗只展示城市徽章正面、超越比例与“收下徽章”按钮，保留入场和缩小淡出的退场动画。领取徽章操作原位更新按钮，保留结果页展开状态与滚动位置。“超越比例”暂由本局分数通过固定曲线估算，并非真实用户成绩统计；商城兑换仍为本机演示，未接入真实优惠核销。

首页「行程助手」、底部 AI 入口及官方挑战结果的「为我规划」打开 AI 行程助手，按用户提供的参考页面呈现目的地标签、想法输入、日期／人数／偏好、我的线路及旅行灵感。输入目的地后使用现有本地资料生成线路，也可手动选择城市；尚未接入在线 AI 规划。结果页进入时预填当前城市，推荐标签读取本轮挑战各场景对应的地点或 POI；点击可逐项加入输入，已收录的线路站点会优先排入路线。切换挑战会更新标签；从首页直接进入时不提前显示未挑战目的地的场景，可输入城市后查看其 POI。改选其他城市规划后仍可返回原挑战结果。舟山卡片为参考示例，未收录进可生成的目的地资料；参考截图裁取素材说明见 `assets/planner/ATTRIBUTION.md`。`node check-itinerary-planner.cjs` 检查生成、保存、重开、返回来源及窄屏布局；通过 `TRIPWONDER_BASE` 指定预览地址。

路线页使用本地策划的景点和兴趣标签生成一至三日安排，可调天数、节奏、兴趣、出发日期，替换和调整停留地点；保存的行程仅在本次页面体验中可查看。已知的周闭馆日及部分开放时段会用于调换日期分组或标出冲突；未收录的开放时间仍需人工核实。交通时长由两点距离粗估，景点停留时间为规划建议；库存、价格、预订与优惠券兑换均未接入。产品按钮仅演示携程业务承接。

原图统一为 `photo-library/<城市>/<景点>/original.<原格式>`，未采用素材集中在 `photo-library/_unused/<城市>/`；目录与加载规则见 [照片素材规范](photo-library/README.md)。`photos.html` 展示采用素材和署名。大同云冈与华严、苏州三景等素材于 2026-10-17 更新为带来源与许可记录的高清横图；悬空寺和深圳城市夜色等既有用户素材保留，未重新认定其拍摄权属。其他城市素材（Pexels、Wikimedia Commons 与 Unsplash 照片）的作者、许可、识别依据和未采用素材，见各城市的 ATTRIBUTION.md / SOURCES.md。`content/*.js` 是景点、线索、题目和路线站点数据；`catalog.js` 汇总八城并建立媒体索引。每个目的地 3–4 处实景（张家界四处，其余三处），题目固定 3 道；全部正式与示例 UGC 场景均按至少 3840×2160 的原生横图验收，记录见 [横图素材审计](photo-library/LANDSCAPE_AUDIT.md)。探索页用 `immersive-viewer.js` 沉浸查看，各景配置见 `immersive-scenes.js`。探索页将原图贴在球体内壁，视点固定在球心，按实际图片比例自动计算转头范围，不依赖深度图。支持任意横图比例，并兼容已有竖图；使用原图分辨率的沉浸素材，支持最高 3 倍放大；切换时以过渡动画覆盖加载，下一处首帧渲染完成后再显示，失败时保留当前画面并可重试。图鉴等非沉浸页面使用缩略图。

探索页按目的地播放背景音乐：八座城市各一首原创配乐（大同《云冈晨钟》、北京《红墙金瓦》、苏州《姑苏塔影》、桂林《漓水青峰》、张家界《峰林云海》、上海《外滩旧梦》、深圳《湾区之光》、香港《维港夜色》），由 `scripts/build-bgm.cjs` 在本地用纯合成音色（拨弦、笛箫、钟磬、人声、合成器与鼓组）生成，不含采样或第三方录音。运行 `node scripts/build-bgm.cjs --ffmpeg <ffmpeg 路径>` 可重新生成 `assets/bgm/*.mp3`（每首约 0.8–1.1 MB，响度约 −18 LUFS）和 `bgm-manifest.js`。城市配乐是一段 60 或 64 秒、PK 配乐是一段 32 秒的循环，均外加 3 秒交接，`scene-bgm.js` 用 Web Audio 每隔一个循环长度启动一份副本，前后副本重叠后无缝衔接。音乐在探索、答题和地图选点环节连续播放，同一目的地内切换页面不中断，离开挑战后淡出暂停。所有 PK 从匹配开始统一播放原创《同频竞逐》（120 BPM、32 秒循环，短促电子拨弦、低频脉冲与轻打击乐），不随玩家 Journey 更换曲目；支持原有静音开关和刷新恢复。使用 `node scripts/build-bgm.cjs --only pk --ffmpeg <ffmpeg 路径>` 可单独重新生成。封面会预取当前目的地的音乐（省流量模式除外）。浏览器要求页面先有一次点击或按键才能出声。直接双击打开 `index.html` 时浏览器不允许读取本地文件，播放器改为加载 `bgm-local/*.js`（同一份 MP3 的脚本封装，由同一脚本生成，只供本地预览，不进入网站和 Android 构建）。打开线索时音乐自动压低，朗读线索时进一步压低；收藏按钮左侧的喇叭按钮可开关音乐，选择保存在本机。`check-bgm.cjs` 检查循环衔接、播放、压低、静音与答题往返。

本轮仍暂缓动态场景。地图边界来自 DataV.GeoAtlas（`assets/map/`），由 `scripts/build-china-map.cjs` 预投影、简化为 `china-map.js`（约 45 KB，省界 + 省会，四色区分相邻省份）；地级市边界另存为 `china-cities.js`（约 112 KB，363 个地市，直辖市/港澳整体显示，DataV 未提供台湾地市数据），只在放大到一定程度时才加载和显示。运行时不解析 GeoJSON、不加载瓦片；平移只移动一个合成层，地图移动时底部卡片暂停实时模糊。确认落点后地图自动缩放，让落点与答案同时完整可见。距离与计分目前在前端计算，文档中的服务端计分尚未接入。`media.js` 保留未来视频接入所需的海报回退与首帧显现能力，但这版各目的地内容都只有静态照片，尚无真实景点视频。浏览器及设备实际表现应以目标手机测试为准。

## 游戏化（本机存储）

社区在「玩家 Journey」右侧提供「我的」页签：「我上传的」只展示带封面、标题和状态的旅程卡片，不显示原型说明、导入或审核工作台按钮；通过右下角「+」继续发布。「我点赞的」汇总点亮红色爱心的 Journey。没有既有个人投稿时初始化一条「把周末交给海风」，使用已有沙坡尾三张授权照片及配套题目，作为独立的本机已发布投稿；初始化记录保存在 IndexedDB，刷新不重复创建、不改动其他投稿，独立管理页仍可编辑及下架。导入的他人旅程不计入自己的投稿；导入和审核功能保留在独立管理页。点赞沿用本机持久存储。`node check-my-uploads.cjs` 检查初始化、照片、刷新、列表清理、打开与编辑及窄屏布局。

## 后台：目的地旅程库（photos.html）与添加 Journey

运行 `node admin/server.mjs`（Node 22+，需要 `node:sqlite`；默认 http://127.0.0.1:8787/，只监听本机），打开 `/photos.html`：

- 按目的地展示，一个目的地一张卡片，点击进入该目的地的场景、讲解点、题目（标注热身 / 原来如此 / 挑战）与规则；内置八城为只读，数据库中的目的地可审核、停用、删除。
- “添加 Journey”（`journey-new.html`）：先选类型——官方（进入今日挑战）或玩家 UGC（需填写不含地名的挑战标题、发布者昵称、是否开启场景留言气泡；审核后进入社区，不参与优惠与成就）；再填写目的地信息、上传 3–9 张场景图、设定规则（挑战总时长、三题分值、定位满分与距离衰减；三题分值 + 定位满分须为 100）。提交后创建后台任务，依次执行：图片转换（thumb / screen / detail WebP；探索页用原图，由球面查看器按需生成） → 每个场景由 MiMo 看图生成 3 个讲解点（只在社区浏览时显示） → MiMo 一次看完全部场景照片，另行生成 3 道由易到难的常识题（不依赖讲解点；不考年份、朝代、人物等书本知识；城市可考人均 GDP、房价等量级，自然风光可考地貌类型）、地图坐标与路线站点 → 校验并写入 SQLite（`admin/data/tripwonder.db`）。步骤失败可从失败处重试，已完成的步骤不会重做。
- 提示词在 `admin/prompts/*.md`，可直接编辑；输出由 `admin/pipeline.mjs` 校验（禁用词防剧透、规则与题库共用 `quiz-rules.js`：题目不考年份、朝代与统计数字，不出方法题，难度按热身 → 原来如此 → 挑战排列、坐标范围、选项与答案位置等），不合格会带着原因自动重试。生成内容默认“待审核”，坐标由模型推断时会标出“待核对”。
- 游戏通过 `/db-journeys.js` 读取状态为“已上线”的数据库目的地：官方目的地由 `catalog.js` 并入今日挑战的目的地池；玩家 UGC 还须“已审核”，由 `community.js` 放进社区；`app.js` 读取每个目的地的 `rules`。静态部署与 Android 构建通过 `admin/export.mjs` 从本机数据库导出审核通过且未停用的 UGC 至 `published-journeys.js`，同时打包照片（Android 使用完整尺寸的 `immersive-blur/photo.jpg`）；每次审核、撤回或停用后需重新构建并发布，已有静态包不会实时收到本机数据库变化。构建机器没有数据库时导出空数组，预置内容与本机投稿仍可使用。`photos.html` 在纯静态部署下退回只读预览。
- MiMo Key 从环境变量 `MIMO_API_KEY`、`admin/mimo.key` 或上级目录的 `mimo api key.txt` 读取，只在服务端使用；模型默认 `mimo-v2.6-flash`（不用 pro）（`MIMO_MODEL` 可改，`MIMO_THINKING=off` 关闭思考以提速）。
- 数据库表 `destination_journeys(destination_id, journey)` 存 journey 文档（JSON），状态与任务另存于 `journey_meta`、`jobs`。

## 历史实验

文创收藏品收集功能已移除，正式页面不再加载彩蛋模块或展示收藏入口。独立历史演示保存在 `demos/hidden-souvenir/`，与正式挑战无关。目的地纪念徽章、城市收藏及社区点图留言保持现有规则。

题库统一维护在 `content/quiz-design.js`：8 个官方目的地和 7 条预置 UGC 共 45 道双语题，全部按 [出题规范](content/QUIZ-SPEC.md) 编写，事实优先取自该场景讲解点（`source` 指向讲解点）。机器可查的规则在 `quiz-rules.js`，由 `npm run test:quiz` 与后台出题流水线共用：题干与选项长度、禁考年份/统计/数数、禁出「怎样判断」类方法题、选项长短均衡、正确答案不总是最长项、答案位置分布。4 条新增预置玩家示例复用现有授权照片，分别编排水巷、山水、渡海与两岸观察路线，作者为示例身份。真实玩家的自编题保留原内容；仅系统初始化投稿随题库版本更新。`npm run test:quiz` 检查题目与 PK 抽池，`node check-player-pk.cjs` 检查随机对战、刷新、结算与再来一场。
