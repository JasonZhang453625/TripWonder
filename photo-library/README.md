# 照片素材存放规范

已采用场景的原图统一存放为 `photo-library/<城市>/<场景>/original.<原格式>`。文件名统一使用 `original`，扩展名使用小写并与实际格式一致；JPEG 使用 `.jpg`，PNG 使用 `.png`，AVIF 使用 `.avif`。移动、重命名时保留文件内容，不为统一名称而转换图片格式。

```text
photo-library/
  <城市>/
    <场景>/
      original.jpg / original.png / original.avif
      photo.json
      thumb.webp
      screen.webp
      detail.webp
      immersive-blur/
        photo.jpg
        provenance.json
  _unused/
    <城市>/
      尚未采用的素材（保留原文件名）
```

`photo.json` 的 `src`、`sourceFile`、`original.src` 都指向本场景的原图。`originalFilename` 保留导入时的文件名；`sourceSha256` 记录原图文件哈希。外部来源页、作者及许可继续记录在城市的 ATTRIBUTION.md / SOURCES.md 和场景内容数据中。

`original` 表示目前取得的本地来源文件；若取得的是来源站提供的高分辨率预览，仍在城市来源说明中标明，不据此称为站点的完整原始上传文件。

苏州虎丘保留了一个方向处理例外：`original.jpg` 是未经此次整理改动的本地来源文件，`oriented.jpg` 是此前已经转正的展示底图，`photo.json.displaySource` 记录其路径与哈希。现有 WebP 和沉浸图继续使用转正后的画面，讲解点位置不变。

## 原型实际加载的版本

| 使用位置 | 图片版本 |
| --- | --- |
| 照片库、图鉴、小卡片、地图回看缩略图 | `thumb.webp` |
| 目的地封面 | `screen.webp` 或 `detail.webp`，由 `media.js` 根据显示需求与网络情况选择 |
| 探索页沉浸画面 | 原图分辨率的 `immersive-blur/photo.jpg`；HTTP 直接加载，`file://` 预览使用 `immersive-<场景 ID>-assets.js` 内嵌版本 |
| 点击查看原始素材 | `original.jpg` / `original.png` / `original.avif` |

沉浸图按来源图的完整像素尺寸构建，保持场景画面比例。方向正确的 JPEG 原样复制；PNG 等来源以 JPEG 98 质量、4:4:4 色度采样保存，不缩小分辨率。运行时仅在尺寸超过设备支持的最大纹理尺寸时按比例缩小。模糊边缘由浏览器根据该图生成，放大上限为 3 倍。缩小下限按照片与屏幕比例计算，可缩到原片外模糊投影的上下边界；宽屏若先触及左右边界，则在该处停止以避免露空。初始视角和双击复位保持 1 倍。

探索页在过渡遮罩下准备下一处场景，完成图片加载、着色器编译及首帧渲染后才切换；不先显示普通图片。加载失败保留当前场景，支持再次点击重试；离开会取消待切换场景。重建命令为 `node scripts/build-immersive-photos.cjs`。

点击进入探索后，优先下载当前场景的完整分辨率沉浸图；首张下载完成便在后台预加载该目的地的其余全部场景。切换复用已下载或正在下载的资源，不重复请求。当前场景显示稳定后，提前异步解码下一张并准备模糊外围，后台不创建额外的显卡渲染器。只准备下一张，当前图与下一张合计超过 4800 万像素（已知低内存设备为 1600 万像素）时，下一张继续保留下载文件，点击时再按原分辨率解码。模糊外围只缩绘原图一次，再镜像小图；清晰主体始终使用原尺寸纹理。

离开探索时取消未完成下载，释放解码图片、显存与临时地址；已完成的 HTTP 图片文件在本次页面体验内保留最多 96 MiB，超限淘汰最久未使用的文件。退出重进、答题后返回可复用这些原始字节，刷新则清空这份内存缓存。`vercel.json` 对带内容哈希版本号的沉浸 JPG 启用一年浏览器缓存，图片更新必须同时更新 `immersive-scenes.js` 中的哈希；其他地址沿用原有缓存规则。部署后才会启用该响应头。后台失败不打断探索，也不自动反复重试，点击对应场景时可重试。

对于 HTTPS 网站，另用 Cache API 保存最多 96 MiB 的版本化图片原始字节，关闭页面再打开也能复用大图，避免浏览器 HTTP 缓存拒绝保存过大的单个文件。写入前按最早保存顺序清理旧图片，同一路径更新版本时清掉旧版本。私密模式、存储权限或额度不足时自动退回正常网络加载；不影响进入探索，不降低清晰度。浏览器或用户清理网站数据会清空这份持久缓存。

修改加载器或查看器源码后运行 `node scripts/build-immersive-viewer.cjs`，重建浏览器包和页面引用版本。`check-scene-performance.cjs` 输出下载、图片准备和首帧耗时，结果是桌面浏览器模拟数据，不代表手机真机网络或性能。发布后运行 `check-online-scenes.cjs`，验证生产网址的版本、首次预加载、HTTP 响应头、关闭页面后重新访问的持久缓存，以及原始图片尺寸。

目的地封面停留 500 毫秒后，会低优先级提前下载即将进入的第一张（或继续探索的那一张）高清沉浸图。封面阶段只下载这一张，其余图片在进入探索后才开始下载；快速切换目的地会取消旧请求。开启系统节省流量时不在封面预取。所有逻辑随网页部署到每个访问设备，不依赖开发电脑上的文件缓存。

## 替换场景照片

1. 将新原图保存到该场景的 `original.<原格式>`，保留来源信息。
2. 同步更新三档 WebP、沉浸图、打包素材，以及尺寸、哈希和路径记录。
3. 按新画面重新核对线索点、讲解、题目及答案解析。
4. 更新页面引用版本并检查照片库、探索页和原图链接。

同一原图不再同时保存在城市根目录或“补充图”目录。完全一致的多余副本核对哈希后移入回收站；未采用素材统一保留在 `_unused`。
